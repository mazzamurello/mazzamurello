# Contracts

Contracts are the parts of the system that outlive any particular
implementation (ADR-0003). Code may be regenerated; contracts change only
through `spec/*` pull requests, and code must conform to them.

| Contract | File | Status | Enforced by |
|---|---|---|---|
| Public HTTP API | [`openapi.yaml`](openapi.yaml) | Phase 0 draft | CI compares the OpenAPI document generated by the server with this contract, after normalizing formatting and ordering; contract tests check responses against it (API-002) |
| Database schema | [`database.md`](database.md) and the migrations | Phase 0 draft | Design tests on the live schema: RLS, ownership columns, roles, security-definer functions (TEN-002, TEN-003, TEN-004) |
| Configuration | [`configuration.md`](configuration.md) | Phase 0 draft | The server refuses to start on missing, invalid or unknown variables; the test harness starts the server with it (ADR-0050) |
| Test harness | [`test-harness.md`](test-harness.md) | Phase 0 draft | The test suite, which follows it to reach the system under test (ADR-0045) |
| Sandbox driver API | [`sandbox-driver.yaml`](sandbox-driver.yaml) | Phase 0 draft | Contract tests between the control plane and the driver (SBX-009) |
| On-disk formats | `formats.md` | Planned (phase 1) | Backup/restore and upgrade tests (OPS-005, OPS-006) |

## Conventions

- OpenAPI documents use version 3.1 and reference requirements with the
  `x-requirements` extension; operations planned for a later phase carry
  `x-phase`.
- Errors are RFC 9457 problem details with a stable `code` (API-007).
- A contract version stays `0.x` until the first release; after it, breaking
  changes follow ADR-0018.
